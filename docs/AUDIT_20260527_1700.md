## 3. 詳細検出結果（severity 降順）

### 3.2 High

#### [AUDIT-perspective-001] O48 service-hub 連携 service-info エンドポイント未実装
- **カテゴリ**: #4 観点反映
- **検出根拠**: perspectives O48（`O48_servicehub_serviceinfo_endpoint`、`require: [マイクロサービス連発]`、`skip_if` に該当せず＝shipyard は週1ペースの連発フリートかつショーケース対象＝service-hub 管理対象）。コード走査で `**/api/hub/**` / `service-info` / `HUB_SHARED_SECRET` が**1 つも存在しない**＝未実装。concept にも shipyard が service-info を公開する設計（§1.1/§6）が無い（§6 は HUB を**消費**する側のみ記載＝論点-001）。
- **影響**: service-hub（内部ダッシュボード）が shipyard 自身の稼働/アプリ層指標を pull できない。フリート運用の片側（双方向性）が欠落。
- **推奨修正アクション**: `/flow:revise <root or service-status>` で `GET /api/hub/service-info` を実装。
  - 最小固定契約: `{ schemaVersion, service: "shipyard", status, version?, metrics?, extra? }`（未確定項目は extra/省略、契約 SoT=service-hub）。
  - 認証: `HUB_SHARED_SECRET`（env、リクエストヘッダ検証、読み取り専用、公開ページとは分離）。
  - `.env.example` に `HUB_SHARED_SECRET` 追記。
- **Class 判定**: **Class A（最小契約は O48 に明文化済 → auto 実装可能）**。ただし service-hub 側の `ServiceInfoResponse` 完全確定は外部依存（論点-001 と同根）のため、本実装は「最小固定 + extra」で先行し、確定後に整合。
- **§8 登録**: 登録推奨（`--auto-register-issues` 未指定）。
